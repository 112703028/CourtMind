# 實驗紀錄：擋拆接觸偵測 + 防守應對（2026-10-20 ~ 10-23）

所有比較都是**同一批資料、同一種切法**，只差被測的那一件事。
擋拆偵測：按片段 5 份聯合交叉驗證、3 個訓練種子、3 模型平均分數、事件 F1（尖峰離標記 ±2 張 = ±0.4 秒內算對；另報 ±1 秒）。
防守應對：按片段 5 份（StratifiedGroupKFold）、三類（換防 / 包夾 / 退防含延誤）每類正確率。

## 一、擋拆接觸偵測（ScreenNet）

- 目前基準：tag `contact_cleanall`、資料 `nba_data_pipeline/output_contact_clean_503`（459 支、32839 窗）。±1 秒 F1 0.839。

### 1. 撞上時間模糊（σ 放寬 / 自適應修正標記）— ❌ 無效

| 3 模型平均 | ±0.4 秒 | ±1 秒 |
|---|---|---|
| B2（σ 0.2 秒）| 0.616 | 0.801 |
| S2（σ 放寬 0.4 秒）| 0.573 | 0.824 |
| Ref（自適應修正撞上時間，±4 張內移到交叉驗證分數最高處）| 0.611 | 0.797 |

- Ref 單一模型有進步（0.562 → 0.589，3 種子都贏），但 3 模型平均已經抵消時間不一致 → 平均後沒差。
- 使用者標記沒有固定前後偏差（修正移動 161/266，往前 90、往後 71）。
- 結論：時間模糊是「撞上」定義本身的模糊，不是標記雜訊。報 F1 時同時列 ±0.4 秒與 ±1 秒。

### 2. 姿態（YOLO11x-pose，直接裁 bbox）— ❌ 撞上那刻不可靠
- 關鍵點信心看起來很高（肩 / 髖 ~100%），但 8 張撞上瞬間人工看：3 錯、2 半錯 —— 兩人重疊時把兩個人的手腳拼成一個骨架（信心照樣高）。

### 3. 反事實軌跡（ghost 模型）— ❌ 被座標雜訊淹沒
- `nba_data_pipeline/ghost_model.py`：SportVU 降到 5fps 重訓「正常跑法」預測（前 1.4 秒 → 後 0.6 秒），訓練時隨機拿掉 1~2 人。SportVU 驗證 ADE 1.59 ft（等速直走基準 2.56）。
- 拿掉掩護者時持球者防守者的預測誤差變化：時間尖峰跟亂猜一樣、真假掩護 AUC 0.40（距離基準 0.80）。
- 原因：在轉播座標上預測誤差 8.95 ft（SportVU 1.6）→ 查出下面的座標問題。
- 附帶發現：Step 1 預訓練是 SportVU **25fps**（10 張 = 0.4 秒），轉播是 5fps（10 張 = 2 秒），時間尺度差 5 倍。

### 4. ⭐ 座標清理 — ✅ +0.053
- **訓練快取的 court_tracks 從來沒去閃爍**（只有 inference.py / 戰術分析有做）→ 訓練與推論不一致。
- 原始：相鄰兩張位移 > 8 ft 佔 **27.5%**（SportVU 0.3%），沒有任何一支片段乾淨。其中 56% 左右鏡像、約 28% 整張 homography 壞、約 16% 單人腳點錯。
- 新增 `tactics_tools.clean_court_tracks()`：鏡像修正（deflicker）+ 壞影格（≤3 張整張跳走又跳回）內插 + 單人尖刺內插 → 大跳動 **5.5%**。
- 接法：`convert_contact.build_windows(clean=True)` → npz 記 `clean_coords=1` → finetune 存進 `data_meta` → `eval_contact.score_curves` 自動清理；`inference.py` 改用 `clean_court_tracks`（`max_run` 依 fps 換算成 0.6 秒）。
- 同 B2 資料：±0.4 秒 0.616 → **0.669**（3 個種子全部贏過 B2 的 3 個種子）；±1 秒 0.801 → 0.783（略降，新片段為主）。

### 5. 新標記（最後一批 283-503）— ✅
- ingest 後新片段共 318 支、330 個掩護（12 支持球者被改過）；screen_192 跳過。
- 清理 + 全部標記 → 上表 0.732。

### 6. SAM3 遮罩
- `run_sam3_tracks.py --save_masks`：遮罩只存 bbox 範圍內、packbits 壓縮（`pack_mask` / `unpack_mask`）。460 支片段共約 400 MB，在 `stubs/train_sam3_masks/`。
- 重跑 SAM3 的編號跟快取不完全一樣（第一支只有 69% 同編號）→ 一律用 bbox IoU ≥ 0.5 對回快取 pid（對到 99~100%）。
- 品質：重疊的人也分得很乾淨（姿態拼錯的那幾張都分開了）。

### 7. 第二階段檢查器（ScreenNet 候選 → 特徵 → 梯度提升樹）— ❌ 只 +0.007
- 特徵模組 `nba_data_pipeline/screen_features.py`（座標：離持球者的防守者、是否擋在持球者–防守者連線上、撞到的是否持球者的防守者…；遮罩：接觸長度、上半身接觸、站姿寬度、接觸持續張數、腳高度差）。
- 「考卷」上（真掩護 vs 靠很近的假掩護）有用：只用距離 AUC 0.672 → 全部特徵 0.787。最強是「撞到的是持球者的防守者」（真掩護 74% vs 困難負例 25%）；接觸高度、跑過來再停、持球者與防守者拉開、腳高度差沒用。
- 但接到 ScreenNet 後面：F1 0.739 → 0.746（理論上限 0.866）。ScreenNet 已經從 2 秒軌跡學到這些關係。**不接進推論**。

### 4. 讓 LLM 自己呼叫面向工具（function calling，`get_facing(who, toward, t_from, t_to)`）
Responses API（gpt-5.5 在 chat completions 不能同時用工具和 reasoning）；154 筆、修正後標記、同樣的範例：
| 版本 | 換防 | 包夾 | 退防/延誤 | 三類平均 |
|---|---|---|---|---|
| A2 距離表 | 71% | 55% | 67% | 65% |
| A2b 同設定重跑 | 69% | 53% | 77% | 66% |
| N + 判讀提示（不給工具）| 69% | 53% | 72% | 65% |
| E + 提示 + 可查面向（只有 7% 題目真的查）| 67% | 66% | 73% | 69% |
| F + 提示 + 每題必須查 Ds→H、Dh→S | 65% | 68% | 73% | 69% |

- **LLM 自身隨機變動大**：同設定重跑 17 題答案不同（淨 +4）、單類可差 10%。
- 判讀提示無效（N ≈ A2）。面向：整體 N → F 淨 +5 題（+3%），跟重跑的雜訊同量級；**包夾兩次面向版本都 66~68%、沒面向的三組都 53~55%**，較不像運氣，但 E 只查 7% 題目卻一樣好 → 不能確定是面向數值本身的貢獻。
- F 每題多一輪 → 費用約兩倍。**暫不加入正式流程**；要確定需全部 402 筆或每版重跑 3 次。

### 6. SportVU 人工包夾（主動學習，2026-10-24）— ✅

### 7. 換分類器 / ScreenNet 當底子（2026-10-24）— ❌
- 同資料、同切法（含 SportVU 包夾），三類平均：**隨機森林 68%**、邏輯迴歸 66%（包夾最好 58%，但退防掉到 72%）、

- `nba_data_pipeline/coverage_net.py`：ScreenNet 主幹（最終模型）看 10 人 18 張軌跡 + 新分類頭（取 H、S、Dh、Ds 摘要 + 其他人平均），
  翻轉 + 雜訊、類別權重；先只訓練頭（60 epoch），finetune 再用小學習率一起微調（LP-FT，20 epoch）：

  |---|---|---|---|---|---|

  | 主幹也微調（5 種切法）| 53% | 42% | 61% | 52% | 72% |

### 結論
- 五種完全不同的方法都錯在同一批包夾 → **問題不在方法，在題目本身**：可能是包夾的標記定義、Dh / Ds 認錯人、或追蹤錯誤（例：screen_16 撞後 0.8 秒掩護者的框跳到防守者 #55 身上）。
- 人工看過之後證實：大部分是**標記問題**（見 3.）。修正後最好的是**隨機森林 + 文字 LLM 混合（三類平均 75%）**，這是目前建議的正式做法。
- 包夾修正後只剩 38 筆，**補包夾標記**比再調 LLM 輸入更可能帶來確定的進步。

## 四、投籃偵測：ACA-Net 用在轉播畫面（2026-10-25）— ❌ 不能直接用

目的：判斷擋拆後有沒有出手（戰術「打得好不好」需要結果）。模型 `mmaction2/work_dirs/acanet/best_acc_top1_epoch_9.pth`
（ACANet + I3DHead，3 類 dribble / layup / shoot，訓練資料是業餘球館單人直式影片，驗證集 94.6%）。

- 做法：SAM3 5fps 框內插回原片 → 每個球員裁下（上下左右補 10%）→ 照訓練構圖貼到 1080×2160 黑畫布中央（人高 = 畫布 58%，訓練中位數）→
  Resize 短邊 128 + CenterCrop 128；2.2 秒窗口、照 `SampleFrames(16, 4, test_mode)` 取幀（不足 64 張循環）。8 支片段 × 每個球員 × 每 0.4 秒一窗。
- 前處理檢查：同一套程式跑 ACA-Net 驗證集 60 支 → **96.7%**（前處理沒錯）。
- 結果：339 個「球員 × 窗口」有 **66% 判成投籃**（絕大多數沒在投，防守者也是 shoot 0.9+）；持球者運球時判對運球只有 **11/34**；
  沒人出手的對照片段（screen_334 / 400）一樣 60–71% 判投籃 → 分不出有投 / 沒投。
- 排除的原因（驗證集 45 支）：
  - 解析度：人縮到 300 / 150 / 100 / 70 px 再放大，全部 96%（轉播球員框高中位 154 px，720p）
  - 只看裁切框：框保留、人塗灰 → 56%（≈ 全猜投籃的 58%）；人保留、框固定大小 → 98% → 模型確實在看動作
- 判斷原因：(1) **沒有「其他」類**，防守 / 站著 / 無球跑動都被硬塞進 3 類，張手站姿最像投籃；(2) 業餘單人固定鏡頭 → 轉播（鏡頭移動、框內有別人）落差太大。
- 另一個獨立問題：擋拆片段只有 3–4 秒，撞上後 ~2 秒就結束，**大多還沒出手**；要看結果需從 `input_videos/yt_src/` 原片往後延長（只有 185 號以後的片段有原片）。
- 下一步候選：SAM3 追球（追球率 100%）軌跡 + 籃框位置的規則式投籃偵測（不用標記）；或比分 OCR 判進球。
- 環境：本地 `mmaction_cpu` conda env（補裝 `timm`）；腳本裡要先設 `mmaction.utils.dependency.WITH_MULTIMODAL = False`
  （vindlu 跟新版 transformers 衝突），ckpt 要 `torch.load(weights_only=False)` 再 `load_state_dict`（torch 2.11 預設 weights_only）。

### 投籃偵測接進戰術分析（2026-10-26）
- 判斷方法（`shot_owner.py`，63 支答案 48 全對 → 改規則後見下）：Roboflow NBA 偵測（籃框 / 跳投 / 上籃 / 球進框）+ SAM3 球 / 球員遮罩。
  出手者 = 離手前 1.5 秒碰球最多的人（排除封蓋者）；投籃動作幅度（出手前最低點 → 空中最高點）≥ 0.9 倍身高、≤ 6 倍（> 6 = 球物體換掉）；
  球離籃框 ≤ 1.0 倍身高或飛出畫面上方 = 強候選。切鏡頭：直方圖或 64×36 灰階像素差 > 45 且 3 張後沒回來（精華剪輯接點多在整數秒 +0.07）。
- **追球一定要 10fps**：用 10fps 資料每隔一張抽掉模擬 5fps 時看不出差別，但**直接用 5fps 追蹤**時，球飛起來那 0.2 秒會跟丟、黏到別的東西上
  （screen_286）；球員遮罩借 5fps 也從 48 掉到 45。→ `run_sam3_tracks.py --ball`：擋拆用的球員維持 5fps，投籃另外用 10fps 追球員 + 球。
- 推論：`inference.py` 讀 pkl 的 `shot_sam3` → `shot_detect.run_rf`（ONNX 權重 `models/rf_basketball_det_v4.onnx`，不需金鑰）+ `detect_shots`
  → `events.pkl` 多 `shots`、`cuts`（出手者編號用 bbox IoU 對回擋拆用的 player_tracks）。
- 戰術：`tactics_tools.screen_outcome` = 同一段鏡頭、擋拆後 8 秒內進攻方第一次出手（出手者角色、幾秒後、區域、三分、類型、進球）；
  出手者隊伍用整段多數決（單張分隊雜訊曾把持球者自己出手判成「防守方出手」）。`tactics_agent` 的 list_screens 帶 outcome，
  提示詞要求進球一律保留語氣（偵測準確率 ~75%）。agent 改走 `coverage_model._llm_client`（MYAI168 轉接，預設 gpt-5.5）。
- 修戰術層一個舊問題：peak 模式的 ScreenNet 事件只有 ±0.3 秒窗，`find_screen_instances` 的幾何接觸（< 3.5 ft）常找不到 → 擋拆被整個丟掉
  （10 支只剩 4 支有事件）。改成幾何找不到就用 peak_frame + 最近的防守者（`contact_geom=False`）。
- 端到端 10 支延長片段（`output_videos/shot_e2e/`，final2 模型、10fps 追球）：出手時間對 9/10（漏 314）；進沒進對 6/9（300、358、233 錯）；
  233 ScreenNet 沒抓到擋拆。成本：SAM3 每支約 3 倍（10 秒片段 ~2 分鐘，3090）。
